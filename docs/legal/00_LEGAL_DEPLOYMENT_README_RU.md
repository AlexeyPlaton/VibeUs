# VibeUs — юридический пакет РФ перед запуском

**Версия шаблонов:** 2026-08-31
**Статус:** рабочие шаблоны для продуктовой и юридической финализации, не замена индивидуальной консультации российского юриста/бухгалтера.

## 1. Что обязательно заполнить перед публикацией

Замените все маркеры вида `[... ]`:

- `[ПРАВООБЛАДАТЕЛЬ]` — ИП / ООО / физлицо со статусом НПД, если выбранная модель допустима;
- `[ФИО / НАИМЕНОВАНИЕ]`, `[ИНН]`, `[ОГРН/ОГРНИП]`, `[АДРЕС / РЕГИОН]` (*LEGAL REVIEW REQUIRED: для самозанятого физического лица в публичном доступе раскрываются ФИО, ИНН, субъект РФ/город и контактные каналы; вопрос обязательности публикации полного почтового адреса/квартиры требует отдельного правового анализа с учетом 152-ФЗ и законодательства о защите прав потребителей*);
- `[EMAIL SUPPORT]`, `[EMAIL PRIVACY]`, `[EMAIL SECURITY]`;
- `[ДОМЕН]` — например `vibeus.pro`;
- `[ХОСТИНГ РФ]`, `[РЕГИОН РФ]`;
- фактический список subprocessors и стран;
- сроки хранения по каждой цели;
- фактический налоговый режим (`BILLING_TAX_MODE=npd` без ККТ либо `BILLING_TAX_MODE=kkt_54fz` с онлайн-кассой) и схема чеков;
- правила возвратов с учетом фактической юридической модели продукта.

Нельзя публиковать шаблоны с незаполненными маркерами.

## 2. Роли VibeUs в обработке данных

### VibeUs как оператор

VibeUs самостоятельно определяет цели обработки как минимум для:

- регистрации и пользовательского аккаунта;
- безопасности аккаунта и anti-abuse;
- биллинга, чеков, бухгалтерского и налогового учета;
- поддержки;
- собственных юридических обязательств.

### VibeUs как лицо, обрабатывающее данные по поручению

Когда клиент VibeUs устанавливает виджет на свой сайт и его посетитель оставляет feedback, именно клиент обычно определяет, зачем собирается feedback и контакт посетителя. Для такого контура VibeUs должен работать по поручению клиента/DPA, а не объявлять себя единственным оператором всех данных.

## 3. Product-law decisions, которые уже должны отражаться в коде

1. **Авторизация пользователей из РФ.** Для владельца ресурса, подпадающего под ч. 10 ст. 8 149-ФЗ, предусмотрены российские способы авторизации: телефон, ЕСИА, ЕБС либо иная отвечающая требованиям информационная система с российским владельцем/контролем. Не делайте Google/GitHub/Apple единственным login для РФ.
2. **Локализация.** С 01.07.2025 при интернет-сборе ПД граждан РФ по общему правилу операции первичного хранения/систематизации и перечисленные в ч. 5 ст. 18 152-ФЗ операции не должны выполняться через базы за пределами РФ, кроме предусмотренных законом исключений.
3. **Согласие отдельно.** С 01.09.2025 согласие на обработку ПД, когда оно является основанием, оформляется отдельно от других подтверждаемых документов. Нельзя прятать его внутрь единого checkbox «принимаю всё».
4. **Роскомнадзор.** По общему правилу уведомление об обработке направляется до начала обработки; трансграничная передача имеет отдельное предварительное уведомление.
5. **Инциденты.** Нужен процесс 24/72 часа для уведомлений уполномоченного органа при инциденте, подпадающем под ч. 3.1 ст. 21 152-ФЗ.
6. **Поручение обработки.** DPA должен содержать перечень данных, операций, целей, требования к конфиденциальности/локализации/безопасности, подтверждающие документы и уведомление об инцидентах.
7. **Онлайн-подписки.** С 01.03.2026 нельзя повторно списывать с реквизитов, от использования которых потребитель отказался; отказ должен приниматься электронно. Для раннего VibeUs рекомендована модель «30 дней, ручное продление» до полного recurring-контроля.
8. **Касса.** Наличие `receipt` в YooKassa API не заменяет проверку фактической ККТ/чека и корректности фискальных реквизитов под ваш налоговый режим.

## 4. Рекомендуемые публичные URL

- `/legal/offer` — оферта/условия;
- `/legal/privacy` — политика обработки ПД;
- `/legal/consent` — отдельное согласие там, где оно реально требуется;
- `/legal/dpa` — поручение обработки для клиентов;
- `/legal/subprocessors` — список привлеченных обработчиков;
- `/legal/retention` — сроки хранения/удаление;
- `/legal/refunds` — оплата, продление, отказ от реквизитов, возвраты;
- `/legal/acceptable-use` — допустимое использование;
- `/legal/security` — публичная security policy;
- `/legal/cookies` — cookies/local storage.

## 5. Что показывать при регистрации

**Обязательное подтверждение договора:**

> Я принимаю условия оферты VibeUs и подтверждаю, что ознакомился с Политикой обработки персональных данных.

Это подтверждение договора/ознакомления, а не формулировка универсального согласия на все обработки.

Если для отдельной цели действительно используется согласие, отображайте **отдельный checkbox/форму**, например для маркетинга:

> Согласен получать продуктовые и маркетинговые сообщения на указанный email. Согласие добровольное и может быть отозвано в любой момент.

Не делайте маркетинговое согласие условием регистрации.

## 6. Что проверить организационно

- карточка оператора и уведомление Роскомнадзора;
- назначение ответственного, если применимо к вашей организационной форме;
- модель угроз/уровень защищенности и меры ст. 19 152-ФЗ;
- журналы доступа и инцидентов;
- договоры с хостингом/почтой/платежами/observability;
- backup location и логирование: они тоже часть data map;
- отдельный реестр трансграничных передач;
- процедура запросов субъекта: доступ, уточнение, блокирование, удаление, отзыв согласия;
- процедура удаления workspace/project и резервных копий;
- DPA с каждым B2B-клиентом, если VibeUs обрабатывает feedback посетителей по его поручению;
- security@ и privacy@ ящики с рабочим SLA.

## 7. До юридической проверки не включать

- автоматическое продление;
- произвольную передачу клиентских данных внешним AI-провайдерам;
- analytics/telemetry, которая уходит за рубеж без data-map и необходимых оснований/уведомлений;
- иностранный social login как единственный вход для пользователей РФ;
- утверждение «полностью соответствует 152-ФЗ/GDPR» без проверки фактической инфраструктуры.
