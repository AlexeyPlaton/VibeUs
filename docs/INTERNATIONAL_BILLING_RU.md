# International Billing Readiness (RF-operated VibeUs)

This document describes the guarded preparation for international hosted billing. It is an operator runbook, not legal, tax, banking, or sanctions advice.

## Current target architecture

- Russian hosted checkout remains on YooKassa in RUB.
- International hosted checkout is prepared for LAVA.TOP in USD.
- Stripe remains optional for self-hosting operators that are independently eligible for Stripe.
- VibeUs hosted international billing remains disabled until provider eligibility is confirmed in writing.

VibeUs uses one-time payments that grant `BILLING_PERIOD_DAYS` of entitlement. The first LAVA integration therefore targets a one-time custom-price invoice, not an automatically recurring mandate.

## Why LAVA is only a candidate until written approval

The current LAVA developer documentation says its API can integrate with an external website/service and that `POST https://gate.lava.top/api/v3/invoice` supports custom amounts in RUB, USD, and EUR. The same documentation currently limits the "Price on request via API" content types to Digital product, Consultation, and Course.

VibeUs is hosted SaaS/software, so technical API compatibility is not enough. Before production activation, obtain written confirmation from LAVA support that the actual VibeUs hosted SaaS use case, operator identity, customer geography, and intended payment flow are accepted under the current agreement.

Official developer documentation: https://developers.lava.top/en
Support: support@lava.top

Do not work around merchant/KYC/country restrictions with inaccurate residency, ownership, address, or business-purpose information.

## Provider configuration

Keep these values disabled/empty in production until approval:

```env
ENABLE_GLOBAL_PRICING=false
GLOBAL_BILLING_PROVIDER=lava
ENABLE_LAVA=false
LAVA_API_BASE_URL=https://gate.lava.top
LAVA_API_KEY=
LAVA_WEBHOOK_API_KEY=
LAVA_OFFER_ID_SOLO=
LAVA_OFFER_ID_STUDIO=
```

`LAVA_API_KEY` authenticates VibeUs requests to LAVA.

`LAVA_WEBHOOK_API_KEY` is a separate high-entropy secret generated by the VibeUs operator. Configure the same value in the LAVA webhook using the "Your service's API key" authentication option. LAVA sends that value in the `X-Api-Key` header. Never reuse `LAVA_API_KEY` for inbound webhook authentication.

## Offers to create after approval

Create one hidden / API-only offer per paid VibeUs tier:

- VibeUs Solo — Price on request via API
- VibeUs Studio — Price on request via API

Record their IDs as `LAVA_OFFER_ID_SOLO` and `LAVA_OFFER_ID_STUDIO`. VibeUs remains the source of truth for the charged amount (`PRICE_USD_SOLO` / `PRICE_USD_STUDIO`); the provider offer must not silently become a second pricing source.

## Webhook activation contract

Configure a LAVA webhook of type **Payment result** over HTTPS and protect it with `LAVA_WEBHOOK_API_KEY`.

The readiness code authenticates the webhook and recognizes `payment.success`, but intentionally does **not** grant an entitlement yet. Before the activation patch is merged:

1. create a real verified LAVA account and offers;
2. send one provider test/real payment that you are permitted to make;
3. capture the exact webhook JSON from LAVA Webhook History with personal/payment data redacted;
4. bind the exact provider invoice identity, amount, currency and event type to the local `Payment` record;
5. make duplicate delivery idempotent (LAVA retries failed webhooks);
6. only after those regression tests pass may the webhook change workspace entitlement.

Do not unlock a paid VibeUs plan from a browser success redirect. Only a verified server-to-server payment event may grant entitlement.

## RF tax/accounting notes for an NPD operator

VibeUs currently supports `BILLING_TAX_MODE=npd`. For services sold through an intermediary participating in settlements, the Federal Tax Service explains that under an agency/commission/mandate arrangement the NPD income date is the last day of the month in which the intermediary received the funds. Confirm that the executed LAVA agreement actually has this legal character before relying on that rule.

Official FNS reference: https://www.nalog.gov.ru/rn71/news/smi/9932795/

NPD also has a current annual income limit and eligibility restrictions. Treat the billing ledger as accounting evidence, not as a substitute for "Мой налог" or professional tax advice.

## USD charge versus USD settlement

A buyer paying a USD-denominated invoice does not guarantee that the operator receives or can retain USD. Provider settlement currency, destination country, payout method, conversion, and fees are a separate layer.

For the initial launch, prefer the payout route that LAVA explicitly approves for the verified RF operator, even if the payout is converted to RUB. Do not open a foreign account merely to bypass a provider restriction.

If the operator later opens a legitimate foreign bank/financial account to retain foreign currency, check Russian currency-control duties before using it. FNS currently states that a resident generally notifies the tax authority of opening/closing/changing details of a foreign account within one month; annual movement reporting can also apply, with statutory exemptions depending on residency duration, jurisdiction, information exchange, turnover and balance.

Official FNS references:
- https://www.nalog.gov.ru/rn77/related_activities/accounting/recording_individuals/notice/
- https://www.nalog.gov.ru/rn77/fl/interest/otfl_dvsredstv/

## Go-live checklist

International checkout remains **NO-GO** until all of the following are true:

- written LAVA approval for the actual hosted SaaS use case and operator;
- merchant/KYC verification complete with truthful data;
- two API-only offers created;
- outbound API key and separate inbound webhook key configured;
- exact production webhook payload captured and regression-tested;
- amount/currency/invoice binding implemented against the local payment ledger;
- duplicate webhook delivery proven idempotent;
- NPD/accounting treatment confirmed for the executed provider agreement;
- payout route tested and understood;
- one end-to-end paid smoke test succeeds;
- only then enable `ENABLE_LAVA=true` and `ENABLE_GLOBAL_PRICING=true`.
