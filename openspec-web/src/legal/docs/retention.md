# Политика хранения и удаления данных VibeUs

**Версия:** 01.09.2026
 
| Категория | Рабочий срок | Основание окончания | Действие |
|---|---:|---|---|
| Активный аккаунт | пока действует аккаунт/договор | удаление аккаунта/прекращение | удалить или обезличить, кроме обязательного хранения |
| Browser sessions | до 7 дней / отзыва | expiry/logout | удалить/отозвать |
| Preview sessions | не дольше tunnel TTL (до 30 дней) | expiry/revoke | удалить/очистить |
| Project feedback | до удаления проекта или аккаунта | удаление/команда клиента | удалить из active DB |
| Security/audit logs | 90 дней | истечение security/claims need | удалить/агрегировать |
| Платежные ledger records | 5 лет (ст. 29 402-ФЗ) | обязательный срок | удалить после срока |
| Support tickets | 1 год после закрытия | закрытие + retention | удалить/обезличить |
| Backups | 30 дней | backup rotation | криптографически/физически уничтожить |

## Правила

1. Удаление из UI должно создавать серверное delete job/audit event, а не только скрывать запись.
2. Soft-delete не является окончательным уничтожением. Для ПД нужен отдельный purge lifecycle.
3. Резервные копии не восстанавливаются в production без повторного применения tombstone/delete ledger.
4. Передача в GitHub/Telegram/внешний AI создает отдельную копию у третьего лица; UI должен честно сообщать, что удаление из VibeUs не гарантирует автоматическое удаление из внешней системы, если API этой системы не поддерживает такое действие.
5. Workspace delete должен отзывать API tokens, access links, preview sessions и интеграционные секреты.
